---
description: Сгенерировать e2e-тест по промту или все тесты (`all`)
agent: build
---

Сгенерируй или перегенерируй e2e-тесты. Аргумент команды: `$ARGUMENTS`.

Режимы:

- `<путь>.prompt.md` — один сценарий.
- `all` или `--all` — все промты `e2e/tests/**/*.prompt.md`.

Если аргумент пуст, не равен `all`/`--all` и не является существующим `*.prompt.md` — остановись и объясни.

Главное правило: меняется только целевой `<scenario>.spec.ts`. Если spec ещё нет — создай его. Другие файлы и папки не создавай и не меняй: ни helpers вне spec, ни `src`, ни документацию, ни конфиги.

- В режиме `all` правило применяется к каждому парному spec.
- Промт не меняется: сценарий правит пользователь.
- Дублирование между specs допустимо.

Перед началом выполни `git status --short` и запомни список изменённых файлов.

Порядок:

1. Прочитай `e2e/AGENTS.md`.
2. Определи целевые промты:
   - для пути — один указанный `*.prompt.md`;
   - для `all`/`--all` — все `e2e/tests/**/*.prompt.md`.
3. Для каждого промта определи парный spec: замени `.prompt.md` на `.spec.ts`. Если в режиме `all` промтов нет — остановись и сообщи.
4. Прочитай каждый промт и сгенерируй самодостаточный spec на raw Playwright. Весь тестовый код — в spec. Импортируй только разрешённые общие константы, типы и утилиты из `e2e/AGENTS.md`; не создавай общих модулей.
5. Если не хватает helper-функции, локатора или подготовки данных — определи их локально в spec.
6. Если не хватает `data-testid`/`data-*` или маршрута:
   - не меняй `src`;
   - для одного промта остановись, spec не создавай и не перезаписывай, сообщи, чего не хватает;
   - в режиме `all` пропусти проблемный промт, перейди к следующему и перечисли все проблемы в конце.
7. Если тест упирается в неверное поведение приложения — не исправляй поведение. Для одного промта остановись и сообщи; в режиме `all` зафиксируй проблемный промт, перейди к следующему и перечисли все проблемы в конце.
8. Отформатируй только целевые specs: `npx prettier --write <specs>`.
9. Запусти `npm run test:e2e:types`.
10. Запусти тесты:
    - один промт: `npx playwright test <spec>`;
    - `all`: `npm run test:e2e`.
11. Если тест упал — исправь только соответствующий spec. Причину в поведении приложения не маскируй.
12. Снова выполни `git status --short` и сравни с исходным списком. Если появились изменения вне целевых specs — перечисли их, откати только свои изменения в запрещённых файлах и сообщи, что задача не выполнена. Чужие изменения до запуска не трогай.
13. В ответе укажи целевые specs, результат типов, результат тестов, список изменённых файлов и подтверждение, что другие файлы не менялись.
